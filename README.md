# Duck! The Stuck
## Video Demo: https://youtu.be/RSHnFOVKveM
### Description:
"Duck! The Stuck" is a puzzle game inspired by Sokoban and Game Boy games written in Godot. The game follows an unnamed duck, controlled by the player, searching for a way to reach the loaf of bread located on every island. You must push rocks, press targets and collect keys in the right order to reach the end of six short levels.
### The Final Project:
I decided to make the final project of my CS50X experience a game above other options for some of the following reasons:
* I wished to get hands-on experience with Godot, a free and open-source engine perfect for simple 2D games. I chose the engine above others like unity for its simplicity and open-source nature, as well as the ample documentation and community support offered.
* Videogame development is a great way to incorporate concepts like object-oriented programming and math principles, which I wish to further learn past the CS50 experience.
* Developing videogames can offer great encouragement whenever progress is made, as you get to experience the changes you make in real time and in action, further driving me to develop when it feels hard to.
### Project Structure:
The project structure is divided in four main folders, along with some files used to detail the git structure, as well as the logo and the project file, used to edit the project with the editor.
#### .godot
The ".godot" folder contains plenty of resources generated by the engine, necessary for the correct execution of the project. As it's generated automatically by the engine, I won't go into detail.
#### assets
The assets folder contains the audio and graphic resources used in the game. Every asset was made by me, the sprites made using Aseprite and the audio using Bfxr.
- **sprites**: The sprites folder contains four images:
  - char_spritesheet.png: Contains the sprites used for "Duck", the playable character, as well as its idle and movement animations.
  - tileset.png: Contains the sprite of each tile in the game, as well as their animations. A single tileset file was used over multiple files to optimize the size and organize the contents in a better way.
  - title_screen.png: A splash screen presented at the start of the game.
  - victory_screen.png: A splash screen shown when the player completes the last level.
- **sounds**: The sounds folder is divided in two folders:
  - **global**: The global folder stores sounds triggered by a user's indirect action.
    - ready_jingle.wav: A small jingle played whenever the character is loaded in.
    - title_screen_jingle: A small jingle played at the start of the game, in the first splash screen.
  - **sound_effects**: The sound_effects folder stores sounds triggered by the interaction of the user with game objects.
    - bonk.wav: A sound effect played whenever the player's movement is obstructed by an obstacle.
    - target_entered.wav: A sound effect played when an object enters a target's collision box.
    - door_open.wav: A sound effect played when a door opens.
    - movement.wav: A sound effect played whenever the player moves a tile.
    - pickup_key.wav: A sound effect played when a key is grabbed by the character.
    - rock_pushed.wav: A sound effect played when a rock is pushed by the player.
#### scenes
The scenes folder stores every scene used in the game. Almost every element with scripted behavior is stored as a scene, which is taken advantage of to ensure they can each be modified without breaking the rest of the game. The scenes folder is divided into two main folders:
- **levels**: Contains the scene used to lay out each level, as well as the title and victory screen. Each level contains a Character scene, a Camera2D node and a TileMap node, the last one used to place every obstacle and graphics into the screen. The title and victory screen each contain a Sprite2D node used to display the appropriate graphic, but the first one also includes an AudioStreamPlayer node and a Timer node, used to play a small jingle and time the change of the scene respectively.
- **stage_elements**: The stage elements are scenes used by the TileMap inside the level scenes, and are essential to the level design and presentation. The stage elements are divided by their role in the TileMap.
  - **decoration**: The decoration folder contains two scene files, each containing a different animated sprite used as backgrounds inside the game.
    - **background_tile.tscn**: The background tile scene contains a looping animation used as the background of the game, specifically, outside the level's window.
    - **waves.tscn**: The waves scene contains a looping animation used as the background inside the level's window.
  - **objects**: The objects folder contains scenes used to build the actual levels of the game, including the character scene and the stage elements. Each scene has its own script to modify their behavior.
    - bread.tscn: The bread scene holds the transition between each level, using an Area2D node to hear whether the player has reached and entered the collision box or not, as well as an animated sprite to show a small animation. The scene also contains a 0.1 sec. timer, used to time the transition instead of letting it happen as soon as the character enters the collision box.
    - character.tscn: The character scene contains all the nodes needed to make the playable character work. Along with a Sprite2D node and a Collision box, an AnimationPlayer node is used to manage the different animations used according to the player's input, a RayCast2D node is used to verify whether an object is in the way the character is facing and three AudioStreamPlayer nodes are used to play sound effects.
    - key.tscn: The key scene used an Area2D and a coliision box to detect the moment in which a player enters, triggering a change which opens the key door. The scene uses an AnimatedSprite2D node and an AudioStreamPlayer node to show a small looping animation and a sound effect when the key is picked up.
    - key_door.tscn: The key door uses a variable to detect when a key has been grabbeed, displacing itself far away to grant passage to the player. It used a Sprite2D node, a Collision box and an AudioStreamPlayer node whenever the door is opened or closed.
    - rock.tscn: The rock scene works as the main obstacle in the game, used to block the player's path while providing a way forwards as interactive objects capable of pressing targets down and opening doors. The main node works is a CharacterBody2D node, and uses a Sprite2D Node for graphics, as well as an AudioStreamPlayer Node for a sound effect. There's also an Area2D held inside the scene labeled as "Hitbox", which is used with the targets, as they don't detect CharacterBody2D nodes entering the defined Area, and using the other Area2D nodes inside the scene would prove troublesome in some circumstances. The main functionality of the scene, however, resides in the four additional Area2D nodes, one for each direction (Up, Down, Left and Right). Each area has a Collision box and a RayCast2D node, which are used to determine where the player is currently standing and in which direction is the rock being pushed towards, checking whether there's an object in the way or not. If the conditions are successfully met, the rock is pushed, otherwise, it's not.
    - target.tscn: The target scene works similarly to the key scene, using an Area 2D node to detect whenever an object enters its Collision box, opening a target door when it happens. However, since it's possible to push rocks or move the character out of the target, a signal is also received anytime the Collision box is exited, returning the door to its original spot. The scene also uses a Sprite2D node and an AudioStreamPlayer node to draw graphics and play a sound effect when an object enters the Collision box.
    - target_door.tscn: As the name implies, the target door works with the target to open and close when the target detects an object entering or leaving. Just like the target is like the key, the target door is similar to the key door, using a global variable to detect when the door should be open and when not. The scene also has a Sprite2D node and an AudioStreamPlayer, as well as the ColisionBox.
#### scripts
The scripts folder contains the script files used to modify each scene's behavior using the GDScript language, Godot's default scripting language. The script files in the project are divided in two categories:
- **global**: The global folder stores scripts loaded automatically by the game at startup. The exception to this is the character script, which is stored here to distinguish its behavior from the scripts in the obstacles folder, since is the only element whose behavior is not tied to the tilemap.
  - character.gd: The character script controls the player's movement, animations and sound effects, using the events passed by the input script.
  - game.gd: The game script contains information on the game's current state, which is often needed in other scenes and scripts, which is why is loaded on startup. This information includes constants like the tile size, the animation speed or the routes of the level scenes, as well as variables like the currently loaded level, booleans on whether the character is holding a key or stepping on a target, and a function to reload the current scene.
  - input.gd: The input script handles the player's inputs by using a variable to set the currently Action Map event being pressed, compared to a constant array of strings with the name of each possible event. The script also detects a call to reload the scene, using the function previously mentioned in the game script.
  - title_screen.gd: The title screen script is only used to handle the timer in the title screen scene, triggering a change of scene to the first level when the timer is over.
- **obstacles**: The obstacles folder holds the scripts for the behavior of items in the TileMap. Due to the similarities in the explanation of the scene files, they will only be listed here, but further information can be found inside the scripts themselves.
  - bread.gd
  - key.gd
  - key_door.gd
  - rock.gd
  - target.gd
  - target_door.gd
